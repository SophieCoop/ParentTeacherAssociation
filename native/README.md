# ועד הורים — האפליקציה לאייפון ולאנדרואיד

המעטפת הנייטיבית של האתר, בנויה על [Capacitor 8](https://capacitorjs.com) — באותה
דרך שבה בנויה האפליקציה של פטק, ומתפרסמת מאותם חשבונות מפתחים (צוות אפל
`9U68Z6M77V`, וחשבון ה-Google Play של פטק).

| | |
|---|---|
| מזהה האפליקציה | `com.vaadhorim.app` (בשתי החנויות; קבוע לתמיד מרגע ההעלאה הראשונה) |
| השם מתחת לאייקון | ועד הורים |
| גרסה | `package.json` ← `version` (כרגע 1.0.0) |
| מספר בנייה | `app-build.json` ← `build`, אחד לשתי הפלטפורמות |
| מערכות | iOS 15 ומעלה (אייפון בלבד); אנדרואיד 7 ומעלה (API 24), יעד API 36 |

## איך זה עובד

- **אותם קבצים באתר ובאפליקציה.** האתר נשאר בשורש המאגר, בלי שלב בנייה.
  `scripts/copy-web.mjs` מעתיק את מה שרשום ב-`web-files.json` אל `www/`, ומשם
  Capacitor אורז אותו לתוך האפליקציה. הטסט `tests/native-files.test.cjs` מוודא
  שכל מה ש-`index.html` טוען נכנס, ושדפים פנימיים (`stats.html`) לא.
- **ההבדלים מתגלים בזמן ריצה**, ב-`js/native.js`: בתוך האפליקציה Capacitor
  מזריק את `window.Capacitor`, ובאתר הוא לא קיים — ואז שום דבר לא משתנה.
  באפליקציה:
  - ההורדה של דוח ה-Excel ושל תמונת הרעיון עוברת לחלון השיתוף של הטלפון.
  - וואטסאפ, חיוג ומדיניות הפרטיות נפתחים מחוץ לאפליקציה.
  - התזכורות מתוזמנות בטלפון עצמו ומגיעות גם כשהאפליקציה סגורה.
  - כפתור החזרה של אנדרואיד סוגר חלון, חוזר לבית, ורק משם ממזער.
  - **כל הנתונים (חוץ מאסימון ההתחברות) מועתקים גם לקובץ** בתיקיית האפליקציה.
    אם אחסון ה-WebView נמחק, הם משוחזרים ממנו לפני שהמסך הראשון מצויר. באנדרואיד
    הקובץ הזה — ורק הוא — נכלל בגיבוי של הטלפון, כך שמי שעובד בלי חשבון לא מאבד
    את הוועד כשהוא מחליף טלפון.
- **קישורי המייל** (אישור חשבון, שחזור סיסמה) נפתחים באתר, בדפדפן של הטלפון.
  אחרי האישור חוזרים לאפליקציה ומתחברים.

## עבודה שוטפת

```
cd native
npm ci                       # פעם אחת, ואחרי כל שינוי ב-package.json
npm run sync                 # מעתיק את קבצי האתר ומסנכרן לשתי הפלטפורמות
```

- **אנדרואיד (לינוקס):**
  `cd android && ./gradlew assembleDebug`.
  - צריך `JAVA_HOME=~/tools/jdk` ו-`ANDROID_HOME=~/tools/android-sdk`.
  - ה-apk נכתב ל-`android/app/build/outputs/apk/debug/`, ומתקינים אותו בטלפון
    מחובר עם `adb install -r`.
  - אין כאן אמולטור: אין KVM במחשב הזה.
  - בודקים את העמוד מ-Chrome: `chrome://inspect`.
- **אייפון (במק):** `npm run sync`, ואז פותחים את `ios/App/App.xcodeproj` ב-Xcode
  ומריצים על סימולטור. אין workspace, כי התוספים מגיעים ב-Swift Package Manager.
  בודקים את העמוד מ-Safari ← Develop.

## גרסה לחנויות

1. **מספר בנייה חדש**, תמיד גבוה מהקודם:
   ```
   node scripts/app-build.mjs set <n>
   ```
   גרסה חדשה (`1.0.1` וכו׳) משנים ב-`package.json`, ב-`versionName` שב-
   `android/app/build.gradle`, וב-`MARKETING_VERSION` שב-Xcode.
2. **אנדרואיד**, על מחשב הלינוקס: `scripts/release-android.sh`.
   - הקבצים נכתבים ל-`~/vaadhorim-android/builds/<n>/`.
   - העלאה ל-Play:
     ```
     node scripts/play-upload.mjs release ~/vaadhorim-android/builds/<n>/vaadhorim-<n>.aab <track> notes.txt
     ```
     `<track>` הוא `internal`, `alpha` (בדיקה סגורה) או `production`.
3. **אייפון**, על המק, מתוך הסשן הגרפי:
   ```
   sudo launchctl asuser "$(id -u)" sudo -u "$USER" -i bash -c \
     'cd ~/Projects/ParentTeacherAssociation/native && scripts/release-ios.sh'
   ```
   הגרסה עולה ל-TestFlight.

## הגדרה חד־פעמית (בעלת החשבון)

### אנדרואיד

1. **מפתח העלאה**, נפרד מזה של פטק:
   ```
   mkdir -p ~/vaadhorim-android && chmod 700 ~/vaadhorim-android
   keytool -genkeypair -v -keystore ~/vaadhorim-android/upload.keystore \
     -alias upload -keyalg RSA -keysize 2048 -validity 10000
   ```
   - ממלאים את `~/vaadhorim-android/keystore.properties` לפי
     `android/keystore.properties.example`, ומעתיקים אותו ל-`android/`. שם הוא לא
     נכנס למאגר.
   - **מגבים את שני הקבצים מחוץ למחשב.** בלי המפתח אי אפשר לעדכן את האפליקציה.
2. **ב-Play Console**, בחשבון של פטק:
   - יוצרים אפליקציה חדשה: שם "ועד הורים", שפת ברירת מחדל עברית (iw-IL), חינמית.
   - מזמינים את חשבון השירות של פטק לאפליקציה (משתמשים והרשאות) עם הרשאת
     שחרור גרסאות.
3. **העלאה ראשונה, ידנית**, מתוך ה-Console: ה-aab לבדיקה סגורה.
   - מקבלים את חתימת האפליקציה של Play (Play App Signing).
   - `play-upload.mjs` יכול לעבוד רק אחרי הגרסה הראשונה, או עם `--draft`.
4. **החשבון פרטי**, ולכן לפני פרסום צריך בדיקה סגורה עם **12 בודקים לפחות, במשך
   14 ימים רצופים**. אחר כך לוחצים "Apply for production access" בדף האפליקציה.
5. **מילוי ב-Console:**
   - Data safety — התשובות המוכנות ב-README הראשי.
   - דירוג תוכן וקהל יעד (מבוגרים).
   - קישור למחיקת חשבון.
   - מדיניות פרטיות: `https://www.vaadhorim.com/privacy.html`.

### אייפון

     שפה ראשית עברית.
   - השם בחנות חייב להיות ייחודי בכל ה-App Store, וייתכן שצריך תוספת ל"ועד הורים".
