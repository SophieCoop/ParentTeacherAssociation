# מיילים של ההרשמה

התבנית `confirm-signup.html` היא מייל אישור ההרשמה, בעיצוב של האפליקציה.
היא נשמרת כאן כדי שתהיה בגרסאות ובשליטה, אבל היא **לא נטענת אוטומטית** —
Supabase שומר את התבניות אצלו, ולכן צריך להדביק אותה פעם אחת בלוח הבקרה.

## 1. הדבקת התבנית

Authentication › Emails › Templates › **Confirm signup**

- **Subject**: `אישור פתיחת החשבון — ועד הורים גן שלנו`
- **Message body**: להעתיק את כל תוכן `confirm-signup.html` ולהדביק.

המשתנים `{{ .ConfirmationURL }}`, `{{ .Email }}` ו-`{{ .SiteURL }}` ממולאים
על ידי Supabase בזמן השליחה. `{{ .SiteURL }}` הוא גם מקור אייקון האפליקציה
שבראש המייל, ולכן הוא חייב להצביע על הדומיין החי.

## 2. שליחה מהדומיין של האתר

כברירת מחדל Supabase שולח מ-`noreply@mail.app.supabase.io`, ויש לכך שתי
עלויות: השם בתיבת הדואר אינו של האפליקציה, והמכסה היא כשני מיילים בשעה —
מגבלה שמורגשת מיד כשכמה הורים נרשמים באותו ערב.

הפתרון הוא SMTP חיצוני: Project Settings › Authentication › **SMTP Settings**.
כל ספק מתאים (Resend, Brevo, SendGrid, Mailgun). התהליך זהה בכולם:

1. לפתוח חשבון אצל הספק ולהוסיף את הדומיין `vaadhorim.com`.
2. להוסיף אצל רשם הדומיין את רשומות ה-DNS שהספק נותן — בדרך כלל
   SPF (`TXT`), DKIM (`TXT` או `CNAME`), ולעיתים DMARC. בלעדיהן המייל
   נשלח, אבל נוטה ליפול לספאם.
3. להמתין לאימות הדומיין אצל הספק.
4. למלא ב-Supabase את פרטי ה-SMTP, ולציין:
   - **Sender email**: `noreply@vaadhorim.com`
   - **Sender name**: `ועד הורים גן שלנו`

אחרי ההפעלה כדאי להעלות ב-Auth › Rate Limits את מכסת המיילים, שנשארת
נמוכה גם כשה-SMTP כבר חיצוני.

## 3. כתובות החזרה

Authentication › URL Configuration

- **Site URL**: `https://www.vaadhorim.com`
- **Redirect URLs**: אותה כתובת, ורצוי גם `https://vaadhorim.com/**`
  ו-`https://www.vaadhorim.com/**`.

האפליקציה מבקשת בהרשמה לחזור לכתובת שממנה נרשמו (`redirect_to`).
כתובת שאינה ברשימה הזו נדחית, ו-Supabase חוזר במקומה ל-Site URL.

## 4. מה לבדוק אחרי שינוי

קישור האישור הוא **חד־פעמי**: לחיצה שנייה עליו תיכשל תמיד עם
`otp_expired`, גם כשהאישור הראשון הצליח. לכן בודקים תמיד עם מייל חדש,
ולא בלחיצה חוזרת על קישור ישן.
