# ועד הורים גן שלנו 🏫

אתר לניהול תקציב, גבייה והוצאות של ועד הורים בגן ילדים.
ממשק בעברית (RTL), עיצוב פסטל צבעוני, מותאם לנייד ולמסך רחב.

## הפעלה

האתר בנוי מ־HTML, CSS ו־JavaScript בלבד — בלי שלב בנייה ובלי התקנות.

**הכי פשוט:** לפתוח את `index.html` בדפדפן (לחיצה כפולה על הקובץ).

**או דרך שרת מקומי** (מומלץ לפיתוח):

```bash
npx http-server -p 8080 .
# ואז לפתוח http://localhost:8080
```

כדי לראות את המערכת מלאה בנתונים לדוגמה: **הגדרות ⚙️ → אזור מסוכן → "טעינת נתוני דוגמה"**.
נתוני הדוגמה מחליפים את המצב כולו, ולכן הם זמינים רק כשאין חשבון מחובר — אחרת הם היו
מוחקים את הנתונים האמיתיים גם מהענן וגם מכל מכשיר אחר שמחובר לחשבון.

## מה יש באתר

### אשף הקמה (5 שלבים — אפשר לדלג על כל אחד)

1. **פתיחת חשבון** — אימייל וסיסמה, לגיבוי ולסנכרון בין מכשירים
2. **פרטי הגן** — שם, כתובת, שנת לימודים ואיש קשר
3. **ילדי הגן** — שמות, ימי הולדת ופרטי ההורים
4. **צוות הגן** — שמות, תפקידים והיררכיה (אופציונלי)
5. **תכנון תקציב** — סעיפי ההוצאה המתוכננים

החשבון נפתח ראשון כדי שכל מה שנכנס בשלבים הבאים יישמר בענן תוך כדי
ההקמה, ולא רק בסופה. **השלב אינו ממתין לאישור המייל:** אם הפרויקט
דורש אישור, המייל נשלח וההקמה ממשיכה מיד; האישור מזוהה ברקע, ומה
שהוזן בינתיים עולה לענן ברגע שהוא מגיע. מי שמדלג ממשיך לעבוד מקומית
ויכול לפתוח חשבון בכל רגע מההגדרות. כשאין ענן מוגדר (`url` ריק
ב-`js/config.js`) השלב נעלם והאשף חוזר לארבעה שלבים.

### לשונית תכנון תקציב 🧮

- כמות הילדים בגן (ניתן לעדכון בכל שלב)
- כמות הצוות וההיררכיה שלו — גננת, סייעת, מטפלת, מורה לחוג
- הוספת שורות סעיפי הוצאה מתוך קטגוריות, עם סכום ותאריך יעד
  (למתי צריך להביא את המתנה)
- קטגוריות ברירת מחדל: מתנה ליום הולדת, מתנה לחג לילדים ולצוות,
  מתנת סוף שנה, חוגים במימון אישי, כיבוד, פעילויות, ציוד, אחר —
  וניתן להוסיף קטגוריות משלכם
- תצוגת הסכום הכולל של כל הקטגוריות ופילוח גרפי

### לשונית גבייה 💰

- כמה כל הורה שילם, באיזה אמצעי — מזומן, פייבוקס, ביט, העברה בנקאית, צ׳ק
- כמה נשאר לשלם, וסטטוס לכל הורה (שולם / חלקי / טרם שולם)
- פריסה לתשלומים עם חישוב אוטומטי של הסכום לכל תשלום
- **ילד שמצטרף באמצע שנה** מקבל אוטומטית אחוז השתתפות מופחת
  לפי תאריך ההצטרפות (וניתן גם לקבוע אחוז ידנית)
- שליחת תזכורת תשלום להורה בוואטסאפ

### לשונית הוצאות 🧾

- ההוצאות בפועל מול התקציב המתוכנן, לכל קטגוריה ובסך הכל
- חישוב היתרה בתקציב ובקופה, והתראה על חריגה

### עמוד סוף שנה 🎈

חישוב כמה להחזיר לכל הורה:

1. סוכמים את ההוצאות בפועל
2. מחלקים אותן ביחידות ההשתתפות (ילד מלא = 1, ילד שהצטרף באמצע שנה = החלק היחסי)
3. לכל הורה מחשבים את חלקו האמיתי בהוצאות ומחסרים ממה ששילם
4. מי ששילם יותר מחלקו מקבל החזר, מי ששילם פחות משלים את ההפרש

כך ילד שהצטרף באמצע שנה משלם ומקבל בחזרה רק לפי אחוז ההשתתפות שלו.

### לשונית פרטי הילדים 🧒

ימי הולדת, שמות ההורים וטלפונים — עם חיוג ישיר ושליחת וואטסאפ.

### לשונית רעיונות למתנות 💡 (סיעור מוחות)

עמוד המחולק לריבועים בכמות בלתי מוגבלת. בכל ריבוע:

- בחירת קטגוריית תקציב מתוך סעיפי ההוצאה שהוגדרו
- בחירת קהל יעד: ילדים / צוות / כיבוד
- שורות של סעיף הוצאה וסכום, עם כפתור להוספת שורות
- תצוגת הסכום הכולל של שורות ההוצאה
- **חלוקת התקציב** בין כל אנשי הצוות / ילדי הגן — כמה יוצא לכל אחד,
  וכמה זה עולה לכל הורה
- בדיקה מיידית אם הרעיון נכנס בתקציב שנותר בקטגוריה
- טבלת השוואה מהירה בין כל הרעיונות

בסוף בוחרים אחת האפשרויות — היא נכנסת ללשונית ההוצאות בפועל
והעלות יורדת מהתקציב.

**שליחה בוואטסאפ להתייעצות** — רשימת ההוצאות של הרעיון נשלחת להורים
כהודעה מעוצבת.

### לשונית תאריכים 📅

לוח שנה חודשי, ימי הולדת של הילדים והצוות, תאריכי היעד של סעיפי התקציב
ואירועי הגן.

### יצירת קשר עם בעל האתר 💬

**הגדרות ⚙️ → עזרה → "כתיבה בוואטסאפ"** פותח שיחה עם בעל האתר, עם שורת
פתיחה שאומרת מאיפה הפנייה — בעל האתר מקבל הודעה ממספר שאינו מוכר לו.

המספר נקבע ב-`js/config.js`:

```js
var SupportConfig = {
  phone: '0501234567'
};
```

כל עוד השדה ריק הכפתור אינו מוצג כלל. שימו לב שהמספר גלוי לכל מי שנכנס
לאתר ובקוד המקור שלו.

### הוספה למסך הבית 📲

האתר עובד כאפליקציה ברגע שהוא יושב במסך הבית: פתיחה בלחיצה אחת, מסך מלא
בלי סרגלי הדפדפן, ואייקון משלו. ההוספה עצמה נעשית בדפדפן, ולכן מה שהאתר
יכול לעשות הוא להסביר איפה הכפתור — וההסבר שונה בין אייפון, אנדרואיד ומחשב.

**מתי ההצעה קופצת.** לא בכניסה הראשונה: מי שזה עתה הגיע עדיין לא יודע אם
האתר מעניין אותו. ההצעה מחכה ל**כניסה השלישית**, ומופיעה במסך הבית אחרי
שסיור ההיכרות כבר רץ. "אולי אחר כך" מרחיק אותה בשלוש כניסות נוספות,
"לא להציג שוב" מכבה אותה לתמיד, ומההגדרות ⚙️ אפשר לפתוח אותה בכל רגע.
טעינות חוזרות בתוך חצי שעה נחשבות אותה כניסה, כדי שרענון לא יקרב אותה.

**מה מוצג.** בכרום ובאדג׳ הדפדפן עצמו מציע התקנה (`beforeinstallprompt`),
ואז מוצג כפתור שמפעיל את חלון ההתקנה שלו. בכל השאר — שלושה צעדים מצוירים
עם האייקון שיש לחפש: כפתור השיתוף באייפון ובספארי שבמק, תפריט שלוש הנקודות
באנדרואיד, אייקון ההתקנה שבשורת הכתובת במחשב. בפיירפוקס במחשב, שאינו יודע
להתקין אתרים, ההצעה אינה מוצגת כלל.

**אזהרת האחסון, ומה עושים כשהאפליקציה נפתחת ריקה.** באייפון (וכך גם
באפליקציה שנוצרת מספארי במק) האפליקציה שבמסך הבית מקבלת אחסון נפרד מזה של
הדפדפן — מה שנשמר במכשיר דרך הדפדפן אינו עובר אליה מעצמו, והיא נפתחת על
מסך הפתיחה של ההקמה כאילו לא היה דבר. הנתונים לא אבדו; הם נשארו בדפדפן.
הטיפול הוא בשני קצוות:

- **לפני ההוספה** — החלון מזהיר על כך ומצביע על שתי הדרכים: חשבון סנכרון,
  או גיבוי לקובץ. בלי כפתור משלו — פתיחת חשבון היא השלב הראשון באשף ההקמה,
  ולכן רוב מי שמגיע לכאן כבר מחובר ומקבל הסבר קצר במקום אזהרה: מתחברים שוב
  באפליקציה החדשה והנתונים נמשכים מהענן. האזהרה נוגעת רק למי שדילג על אותו
  שלב, וקריאה לפעולה בגודל כזה הייתה מתחרה בתפקיד של החלון. בכרום ובאדג׳
  האחסון משותף ואין מה להזהיר.
- **אחרי ההוספה** — מסך הפתיחה של אפליקציה ריקה מציע את ההתחברות לחשבון,
  וממנה הנתונים נמשכים מהענן.

`manifest.webmanifest` נותן לאנדרואיד ולמחשב שם, אייקון ופתיחה במסך מלא;
באייפון אותו תפקיד ממלאות תגיות ה-`apple-mobile-web-app-*` שב-`index.html`.
אין Service Worker ואין קאשינג: האפליקציה שבמסך הבית טוענת את אותם קבצים
מהרשת כמו הדפדפן, ולכן היא אינה נפתחת בלי חיבור. מה שההוספה נותנת הוא
הנוחות — אייקון, פתיחה מיידית ומסך מלא — ולא עבודה במצב לא מקוון.

## הנתונים שלכם

הנתונים תמיד נשמרים קודם כל **במכשיר** (`localStorage`), ולכן האתר מיידי
ועובד גם בלי אינטרנט. מעל זה יש **סנכרון אופציונלי לענן**.

### בלי התחברות — מקומי בלבד

ברירת המחדל. הנתונים נשמרים על המכשיר ולא נשלחים לשום מקום.
הם לא עוברים בין מכשירים, וניקוי נתוני הגלישה ימחק אותם —
לכן מומלץ לייצא גיבוי מדי פעם דרך **הגדרות ⚙️ → ייצוא גיבוי**.

### עם התחברות — סנכרון בין הטלפון למחשב

חשבון נפתח בשלב הראשון של אשף ההקמה, או בכל רגע מאוחר יותר
מ**הגדרות ⚙️ → "סנכרון בין מכשירים"**. מאותו רגע כל שינוי עולה לענן
ונמשך אוטומטית במכשיר השני (בעלייה של האפליקציה ובכל חזרה אליה).
במכשיר חדש מתחברים ממסך הפתיחה — **"כבר יש לי חשבון"** —
והנתונים נמשכים אליו.

**אישור מייל.** אם הפרויקט ב-Supabase דורש אישור כתובת (ברירת המחדל),
ההרשמה אינה נעצרת בשבילו: מוצג "המייל בדרך", ההקמה ממשיכה, והאישור
מזוהה ברקע — בכל חזרה ללשונית, ובנוסף סקירה אחת ל-20 שניות במשך חמש
דקות (מרווח רחב בכוונה, כדי לא להיתקל בהגבלת הקצב של שרת ההתחברות).
אפשר גם ללחוץ "כבר אישרתי — בדיקה עכשיו". ברגע שהאישור מזוהה, כל מה
שהוזן עד אז נדחף לענן והמשתמש מקבל הודעה קצרה.

כדי שההרשמה תסתיים מיידית בלי מייל כלל: Supabase → Authentication →
Sign In / Providers → Email → **Confirm email** כבוי. זו הגדרת שרת,
ולא משהו שהקוד יכול לעקוף.

שימו לב ששרת המייל המובנה של Supabase מוגבל לכמה הודעות בשעה
ומיועד לפיתוח בלבד — לשימוש אמיתי צריך להגדיר SMTP חיצוני.

שבב מצב בראש מסך הבית מראה תמיד מה קורה: מסונכרן, ממתין, מסנכרן,
אין חיבור, או התנגשות.

**מה קורה כשעורכים בשני מכשירים במקביל?** המצב נשמר כמסמך אחד, ולכן
העיקרון הוא "האחרון מנצח". כדי שגרסה לא תימחק בשקט, האפליקציה מזהה
שגם המכשיר וגם הענן השתנו מאז הסנכרון האחרון, עוצרת, ומציגה את שתי
הגרסאות עם מספר הילדים, התשלומים וההוצאות בכל אחת — ואתם בוחרים
איזו לשמור.

**איפה זה יושב:** טבלה אחת (`vaad_state`) ב-Supabase, שורה אחת לכל
משתמש, עם מדיניות RLS שמאפשרת לכל משתמש לקרוא ולכתוב אך ורק את
השורה שלו. פרטי החיבור נמצאים ב-`js/config.js`; המפתח שם הוא מפתח
ציבורי (publishable) שנועד לרוץ בדפדפן — ההגנה היא ב-RLS בצד השרת.

כדי לכבות את הסנכרון לגמרי ולחזור למצב מקומי בלבד: לרוקן את `url`
בקובץ `js/config.js`.

### הקמת הענן מאפס (אם רוצים פרויקט Supabase משלכם)

```sql
create table public.vaad_state (
  user_id    uuid primary key references auth.users (id) on delete cascade,
  data       jsonb       not null default '{}'::jsonb,
  updated_at timestamptz not null default now(),
  device     text
);
alter table public.vaad_state enable row level security;

create policy "vaad_state_select_own" on public.vaad_state
  for select using ((select auth.uid()) = user_id);
create policy "vaad_state_insert_own" on public.vaad_state
  for insert with check ((select auth.uid()) = user_id);
create policy "vaad_state_update_own" on public.vaad_state
  for update using ((select auth.uid()) = user_id)
  with check ((select auth.uid()) = user_id);
create policy "vaad_state_delete_own" on public.vaad_state
  for delete using ((select auth.uid()) = user_id);
```

ואז לעדכן `url` ו-`key` ב-`js/config.js`.

## מדידת שימוש

האתר מדווח ל-**Vercel Web Analytics** — ללא עוגיות ובלי מעקב חוצה-אתרים.
הסקריפט נטען ב-`index.html` מ-`/_vercel/insights/script.js`, ו-Vercel מגישה
אותו רק כשהמדידה מודלקת בפרויקט (Project → Analytics → Enable). בלעדיה,
ובפיתוח מקומי, הסקריפט פשוט לא נטען והקריאות נעלמות בלי להשפיע על כלום.

**למה צריך אירועים מותאמים.** האפליקציה יושבת בעמוד אחד, והמעבר בין
המסכים משנה רק את האש בכתובת (`history.replaceState`). Vercel סופרת צפיות
לפי נתיב, ולכן מהקופסה היה נספר ביקור אחד בלבד ב-`/`. לכן `App.setView`
מדווח בעצמו על כל מעבר מסך.

**מה נמדד:** מסך שנפתח (`view`), התקדמות בשלבי אשף ההקמה (`wizard-step`),
סיום הקמה עם חשבון או בלי (`setup-done`), פעולות חשבון (`account`:
פתיחה, התחברות, אישור מייל), וההצעה להוסיף למסך הבית (`install`: הוצגה,
נפתחה מההגדרות, בוצעה, נדחתה, כובתה).

**מה לא נמדד, לעולם.** באפליקציה יושבים שמות ילדים, שמות הורים ומספרי
טלפון. `js/analytics.js` בנוי כרשימה סגורה: כל שם אירוע וכל ערך אפשרי
בכל שדה מוגדרים בקוד מראש, וערך שאינו ברשימה מבטל את האירוע כולו במקום
להישלח. גם קוד עתידי שינסה לצרף שדה מהנתונים לא יעבור. בנוסף, `beforeSend`
ב-`index.html` מקצץ מהכתובת את האש ואת הפרמטרים לפני השליחה.
